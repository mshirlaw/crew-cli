# AGENTS.md

Guidance for AI coding agents (and humans) working on this repo: what crew is, how it's built, and the decisions behind it. Read this before changing anything.

## What crew is

`crew` is a single bash script that starts a team of AI coding agents (Claude Code, Codex, Gemini, or any CLI) in herdr or tmux. Each agent gets a role, its own git worktree, and a shared message board. The human talks to the lead; agents message each other with `crew say` and track work with `crew task`.

## Layout

| Path | What it is |
|---|---|
| `crew` | the whole tool |
| `install.sh` | installer: works from a clone or via `curl ... \| bash`; `--uninstall` |
| `config.example.toml` | sample global config, generated by `crew config example` |
| `test/run.sh` | test suite (stand-in agents, real tmux, fake herdr) |
| `.github/workflows/test.yml` | CI: shellcheck and tests on Linux and macOS (bash 3.2) |

In a repo where crew runs, everything lives in `.crew/`: `config.toml`, `roles/*.md`, `PROTOCOL.md` (generated), `board.md`, `tasks.tsv` with `tasks.md` (generated), `notes/`, and `state/` (session ids, watcher pid).

## Rules for changing crew

- Keep it **one bash file that runs on macOS's stock bash 3.2**. No associative arrays, `mapfile`, `${var,,}`, `|&` or other bash 4+ features. CI runs the tests under `/bin/bash` on macOS.
- **No new dependencies.** Required: git plus herdr or tmux 3.0+. jq or python3 is needed only for herdr's JSON.
- **Small single-purpose functions, each with a one-line plain-English comment** saying what it does. Command functions (`cmd_*`) should read as a list of steps.
- Run `test/run.sh` and `shellcheck crew install.sh test/run.sh` before committing. Add a `check` line for any behaviour change.
- If you change `global_config_template`, regenerate the sample with `./crew config example > config.example.toml`. A test enforces this.
- Bump `CREW_VERSION` for user-visible changes.

## Decisions and why

These were settled while building crew. Don't reverse one without a good reason, and record any new decision here.

### Shape of the tool
- **A bash script, not Python or Go.** It must run anywhere herdr or tmux runs (including a Raspberry Pi) with nothing to install.
- **Named `crew`, no `.sh`.** It's a command people type; the `#!` line picks the interpreter. `install.sh` keeps its extension because it's a one-off script.
- **Agents are disposable; files are the memory.** Roles, board, tasks and handoff notes are files, so a killed agent loses nothing. A restarted agent is told to read `notes/<role>.md`.

### Sharing across worktrees
- **Each role (except the lead by default) gets a git worktree** under `~/.crew/worktrees/<repo-slug>-<hash>/<role>` on branch `crew/<role>`. They live outside the repo so test runners and file watchers don't see duplicate code.
- **There is exactly one `.crew/` folder**, in the main checkout. Worktrees don't get a copy (it's untracked). Agents reach it by absolute path, launch flags give them access (`--add-dir`, `--include-directories`, the `{crew}` placeholder), and `CREW_DIR` is set in each pane so `crew` finds it from any worktree.
- **`.crew/` is hidden through `.git/info/exclude`,** not `.gitignore`, so crew never changes tracked files.
- **Only the lead agent merges** `crew/*` branches into the base branch, locally. crew itself never pushes, merges or deletes branches.

### Messaging
- **`crew say` appends to `board.md` and types the message into the recipient's session.** herdr uses `herdr agent prompt`, which refuses while an agent is blocked; tmux pastes with `paste-buffer -p`, waits `paste_delay` seconds (default 0.3), then presses Enter.
- **The protocol forbids acknowledgement-only messages** ("ok", "thanks") to stop agents looping.
- `say all` goes to everyone except the sender. Messages from `crew` itself don't count as owed replies.

### Configuration
- **TOML, not YAML.** It's flat and doesn't depend on indentation, so a small awk parser reads it with no dependency. Only a subset is supported: sections, strings, numbers, true/false. No arrays.
- **Two layers: `~/.config/crew/config.toml` (global) and `.crew/config.toml` (repo); repo wins.** Roles are read only from the repo file. Global roles are a template that `crew setup` copies and `crew role save` replaces.
- **Agent launch commands are config, not code:** `command = "claude --add-dir {crew}"` with `{crew}`, `{repo}`, `{role}`, `{prompt}` placeholders. The kickoff prompt is appended unless `{prompt}` is used. Placeholders are substituted per word after splitting, so paths with spaces stay intact.
- **herdr `kind`** defaults to the agent's name when herdr knows it (list copied from herdr 0.9.5). Then crew uses `herdr agent start` for naming and status tracking; `kind = ""` makes herdr type the command instead.
- **Settings must sit above any `[section]`** to be top-level. That's TOML, and the docs say so.
- **The installer creates the global config** with `crew config init`, choosing herdr if it's installed, otherwise tmux. It never overwrites an existing config.

### Multiplexers
- **herdr and tmux are interchangeable backends.** `mux <action>` calls `<multiplexer>_<action>` (e.g. `tmux_split`, `herdr_split`). Adding one means implementing the same set of actions.
- **tmux can only report running or stopped.** An agent counts as running when the pane's shell has a child process. It isn't matched by process name, because many agent wrappers are shell scripts.
- **The tmux layout is `main-vertical`:** the first role on the left, the rest stacked on the right, plus a `board` window tailing `board.md`.
- **State records which multiplexer created it.** Switching multiplexers discards stale pane ids instead of reusing them.

### Tasks
- **Tasks live in `tasks.tsv`; `tasks.md` is generated** after every change. Agents read `tasks.md` and change tasks only with `crew task add | set | done`.
- **A `mkdir` lock** guards every change, because `flock` isn't on macOS. A lock older than 10 seconds is treated as stale. Values reach awk through the environment, not `-v`, so backslashes survive.

### Stalled agents
- **Generic detection, not matching agents' error messages.** The human decided against hard-coding each agent's "usage limit" wording, because it's brittle and changes between versions. Instead: an agent is stalled when it **owes work** (a todo or doing task it owns, or a board message to it, or to all, posted after its own last message) **and its screen hasn't changed for `stall_timeout` seconds** (default 600; 0 turns it off).
- This catches running out of tokens, waiting on an approval, crashes and hangs alike. An idle agent with nothing owed is never flagged, and a busy agent's spinner keeps its screen changing.
- **The lead is told once per stall** (on the board and in its session) so it can check or reassign the work. If the lead stalls, or there's no lead, the human is told: board, plus a herdr notification or the tmux status line.
- **`crew start` runs `crew watch` in the background** (pid in `state/watch.pid`); `crew stop` kills it and its `sleep`. The watcher also exits when its pid file disappears, or after 3 checks with no session.

### Upgrades
- 0.2's `.crew/crew.conf` is converted to `.crew/config.toml` automatically (the old file is kept as `crew.conf.old`). A hand-written `tasks.md` from 0.2 or 0.3 is moved to `tasks-old.md`.
